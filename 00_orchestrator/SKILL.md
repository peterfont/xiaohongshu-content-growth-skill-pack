# 小红书内容实验总控

## 核心目标

不要把流程理解成“选题 → 写文案”。

正确链路是：

> 素材 → 选题 → 行为预测 → 内容架构 → 发布形态选择 → 图文视觉结构 → 文案生成 → 发布前质检 → 发布 → 数据复盘 → 规则学习 → 下一轮

其中最关键的新层是：

> **行为预测必须转译成内容结构约束。**

例如：

预测“评论高”，不能只在结尾随便加一句“你怎么看”。

必须在整篇内容中主动设计：
- 身份代入
- 未闭合问题
- 观点空间
- 低门槛表达
- 不把答案说死
- 可供用户补充自己的经历

预测“收藏高”，则必须主动设计：
- 可复用方法
- 结构化步骤
- 判断标准
- 清单
- 以后还能回来查的内容密度

## 调用顺序

1. `topic-planner`
2. `behavior-predictor`
3. `content-architect`
4. `format-selector`
5. `visual-architect`
6. `content-generator`
7. `preflight-checker`
8. 发布
9. `performance-analyst`
10. `strategy-learner`

## 每一步的输出必须成为下一步的输入

禁止技能之间各自独立工作。

例如：

Behavior Predictor 输出：
- 主行为：评论
- 次行为：关注
- 必须机制：身份共鸣、开放问题、系列承诺
- 禁止事项：不要过早给完整答案

Content Architect 必须把这些要求变成：
- 开头结构
- 中段结构
- 结尾结构
- CTA
- 搜索关键词
- 人设信息
- 证据材料

Content Generator 必须严格按蓝图写。

Preflight Checker 必须逐项检查是否真的执行。

## 发布前最低产物

每篇内容都必须有：

### 1. 选题卡
- 目标用户
- 用户问题
- 核心矛盾
- 内容目标
- 五维标签

### 2. 行为预测卡
- 点击
- 停留
- 点赞
- 评论
- 收藏
- 分享
- 关注
- 搜索
- 商业咨询

### 3. 内容蓝图
- 开头承诺
- 主体段落
- 每段承担什么行为任务
- 证据
- CTA
- 搜索关键词
- 人设/系列承接

### 4. 发布前质检
- 是否兑现预测所需结构
- 是否有题文一致
- 是否有证据
- 是否有过度解释
- 是否缺少行为触发点

## 核心原则

> 预测不是结论，而是待验证假设。

> 内容不是文字，而是对用户行为的结构化设计。

> 每一篇只设一个主行为，最多两个次行为。

> 不要用同一指标评价所有内容。

> 每次实验最多主动修改 1～3 个变量。


# v5 产品推广完整链路
产品 → 用户任务 → 账号定位 → 竞品对标 → 推广计划 → 单篇选题 → 行为预测 → 内容架构 → 发布形态 → 图文视觉结构 → 文案生成 → 发布前质检 → 发布 → 数据复盘 → 策略学习。

账号定位、竞品对标、推广计划属于周期级决策；单篇发布时从选题开始执行。
